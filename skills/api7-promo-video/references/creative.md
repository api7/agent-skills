# Brief and visual direction

Record product, videoType, explicit target duration, audience, topic,
source/version, language, aspect, narration/captions, proof, CTA text/URL and
publication permissions. Select the structure using [Video types](formats.md).
A release announcement can focus on one change; a complete topic can use
chapters and operation/result sequences. Keep one promised viewer outcome.

## Format is a content decision

| Content | Default | Layout |
|---|---|---|
| One feature, request flow, large text | square, 1080×1080 | One focused stage; stacked title and proof |
| Wide UI, code, architecture comparison | landscape, 1920×1080 | Wide proof area; no tiny window in empty space |
| Mobile-first story or spoken social film | portrait, 1080×1350 | Vertical sequence and platform-safe captions |

The scaffold uses `aspect: square`, `landscape` or `portrait`. Here `portrait`
means 4:5, not 9:16. Only create extra versions when requested; rebuild the layout
for each ratio. Honor an explicit requested ratio over these defaults.

## Approved house treatment

Read [Approved feed style](approved-feed-style.md) for authored promos. It carries
the approved palette, one Inter400/700 system, card continuity, setup alignment,
and video/post/technical-note separation. The model-support card format defaults
to16:9; other subjects follow the content table above and explicit user ratios.
The old flow starter remains a layout draft for illustrative request stories;
it is not the announcement's motion template.

Use the approved restrained brand light pools where appropriate rather than
banning all gradients. Keep one primary brand accent, official marks and clear
space. For another product, use its own identity; for a different user direction,
record the intentional override in SPEC.md. Give real UI/code room to be read.

When explicitly asked for maximum reference fidelity, read
[Reference fidelity](reference-fidelity.md). Preserve observed action speeds,
then budget holds for the requested duration. The user's approved Inter system,
brand palette and copy simplification take precedence over copying the source's
blue/green colors or monospaced decoration. State what was actually inspected.

## Sound and post

For a brief feed promo, English visual copy and a light instrumental bed can
work without narration. For explanations/tutorials/demos, plan the requested
narration and synchronized captions around actions. Honor the user's audio
choice; length alone does not authorize paid voice generation. Add a few
cause-linked effects only when useful. Prefer fitting free commercial-use music
without mandatory public credit.
Verify and record source, license and edits internally; include public credits
only where the license requires them. Missing authorized music is a delivery gap
to report, not a
reason to fabricate a track or silently purchase one.

Write 40–70 English words for the post body (or equivalent concise copy in the
requested language). Lead announcements with what is new, and feature explainers
with the problem.
Name the capability and verified scope; end with the same CTA used on screen
and its URL. Move complex parameter/accounting details to separate technical
notes; do not hide a caveat that changes the advertised promise. Put required asset
credits below the body; credits do not count toward the word target. Use one
link/destination, no unrelated demo, sales and newsletter CTAs together.

Create SPEC.md and STORYBOARD.md with timings, exact copy, colors, type sizes,
motion and proof. Each readable line holds ≥0.5 s + 0.3 s per word. Treat the
scaffold as a draft: adapt the visual device to the topic, not just the nouns.
